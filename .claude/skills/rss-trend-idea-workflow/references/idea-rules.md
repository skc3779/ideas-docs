# 아이디어 도출 규칙 (Step 3 전용)

원본: `02_skills/01_트렌드_구글_검색_v2.md`. 이 파일은 Step 3에 필요한 규칙만 추리고, 기존 결과물에서 드러난 문제(점수 인플레이션, 아이디어 반복, 근거 오염)를 막는 규칙을 더했다.

## 1. 입력 데이터 사용 규칙

- `수집상태 == "성공"`인 항목만 근거로 쓴다. `요약정보`가 `실패 사유:`로 시작하는 항목은 근거로 인용하지 않고, 메인 파일의 수집 개요에 실패 건수로만 적는다.
- 근거 링크는 JSON 값을 **그대로 복사**한다. `원문링크`가 있으면 원문링크, 없으면 `link`를 쓴다. 링크를 지어내거나 줄이지 않는다.
- 수치·고유명사·날짜는 `요약정보`와 `title`에 있는 것만 쓴다. 요약에 없는 시장 규모나 통계를 사실처럼 적지 않는다. 추정이 필요하면 `(추정)`이라고 표시한다.
- 성공 항목이 8건 미만이면 메인 파일 수집 개요에 "데이터 한계"를 명시하고, 점수 근거에도 반영한다.

## 2. 트렌드 분석 포인트

1. 반복 키워드: 2개 이상 항목에 나오는 주제나 기술
2. 수요 신호: 불편, 관심, 지출 의향, 규제나 정책 변화
3. 실행 가능성: 기술 난이도, 초기 비용, 시장 진입 난이도

## 3. 카테고리 (정확히 1개씩, 총 4개)

| 파일명 키 | 영역 | 세부 카테고리 |
|---|---|---|
| `Software` | 소프트웨어 | B2B SaaS, DevTools, Cybersecurity |
| `DataAI` | 데이터 및 인공지능 | LLM App(RAG/에이전트), DataOps, Vertical AI, MLOps |
| `ITServices` | 서비스 및 플랫폼 | Marketplace, 디지털 헬스케어, 핀테크/인슈어테크, 에듀테크 |
| `Media` | 유튜브 콘텐츠 및 미디어 | AI 자동화 채널, 버추얼 휴먼/IP, 인터랙티브, 콘텐츠 분석 |

- 4개 아이디어는 **서로 다른 문제나 수요**를 다뤄야 한다. 같은 기사 하나로 아이디어 4개를 모두 만들지 않는다.
- 각 아이디어는 **최소 1개, 가능하면 2개 이상의 서로 다른 RSS 항목**에 근거한다.

## 4. 이전 실행과의 중복 방지

- 같은 폴더의 직전 `*_idea_Main_Summary.md`에서 아이디어명 4개를 확인한다.
- 같은 아이디어를 반복하지 않는다. 새 근거로 같은 주제를 다시 다룰 때는 아이디어명 옆에 `(후속)`을 붙이고, 이전 실행 대비 무엇이 달라졌는지 한 줄로 적는다.

## 5. 실현 가능성 점수 (1~5 **정수**)

| 점수 | 의미 | 대표 조건 |
|---|---|---|
| 5 | 즉시 실행 가능 | 1~2인이 3개월 안에 기존 API/오픈소스로 MVP 가능 + 수요 근거가 2개 이상 항목에 있음 |
| 4 | 실행 가능, 일부 검증 필요 | MVP는 가능하지만 유료 전환, 데이터 확보, 파트너 중 하나를 검증해야 함 |
| 3 | 보통, 핵심 가정 검증 필요 | 핵심 기술이나 데이터 접근이 불확실하거나, 수요 근거가 1건뿐임 |
| 2 | 리스크 높음 | 규제 인허가, 하드웨어, 대규모 자본, 독점 데이터 중 하나 이상이 선행 조건임 |
| 1 | 현재 실행 어려움 | 기술이 미성숙하거나 진입 장벽이 사실상 넘기 어려움 |

보정 규칙(인플레이션 방지):
- `4.5 / 5`처럼 소수점을 쓰지 않는다. 검증기가 FAIL로 처리한다.
- 반도체 설계, 의료기기·DTx 인허가, 금융 라이선스, 하드웨어 양산이 필요한 아이디어는 **최대 3점**이다. 더 높게 주려면 그 장벽을 우회하는 구체적 MVP 경로를 근거에 적는다.
- 4개 모두 같은 점수면 다시 검토한다. 점수 차이가 없으면 평가표가 의사결정에 쓸모가 없다.
- 점수 근거는 **기술 난이도 / 초기 비용 / 시장 진입 / 수요 신호** 네 줄로 적는다.

## 6. 파일 규칙

- 실행시간(`RUN_ID`)은 step2.py가 마지막 줄에 출력한 `실행시간: YYYY-MM-DD_HHMMSS` 값이다. 폴더마다 다르며, 다른 폴더 값을 재사용하지 않는다.
- 메인: `{RUN_ID}_idea_Main_Summary.md`
- 상세: `{RUN_ID}_idea_{카테고리키}_{아이디어명}.md`
  - 카테고리키: `Software` | `DataAI` | `ITServices` | `Media`
  - 아이디어명: 영문 PascalCase 또는 하이픈 사용, 공백 없음 (예: `Forex24-Guard`, `PromptBranch`)
- 모든 파일 **첫 줄**은 `실행시간 : {RUN_ID}`이다.
- 기존 파일을 덮어쓰지 않는다. 같은 이름의 파일이 이미 있으면 중단하고 사용자에게 알린다.

## 7. 품질 체크리스트 (작성 후 자체 점검)

- [ ] 아이디어가 정확히 4개이고, 카테고리 4개에 1개씩 배정됐는가
- [ ] 점수가 1~5 정수이고, 네 줄 근거가 있으며, 보정 규칙을 지켰는가
- [ ] 근거 링크가 JSON에 있는 값 그대로이고, 실패 항목은 인용하지 않았는가
- [ ] 상세 파일에 문제 정의, 타겟, 핵심 기능, MVP, 수익 모델, GTM, 로드맵, 리스크가 모두 있는가
- [ ] 직전 실행과 아이디어가 겹치지 않는가 (겹치면 `(후속)` 표시)
- [ ] `check_outputs.py`가 PASS인가
