# LeanProof-Audit: AI가 생성한 초대형 Lean 증명을 사람이 검토할 수 있게 만드는 감사 도구

## 1. 제안 범위 및 카테고리
- **영역**: 소프트웨어 (Software)
- **세부 카테고리**: DevTools (형식 검증 / 코드 감사)
- **직전 실행과의 관계**: 신규

## 2. 해결 문제와 사용자 페르소나
- **문제 정의**: 앤트로픽 연구원이 클로드와 함께 리만 가설 증명을 주장하며 Lean으로 작성한 1740만 줄의 코드를 공개했다. AI가 쓴 설명은 25만 쪽을 넘어 글로 풀어 쓰는 것을 포기했고, 주장은 아직 독립 검증이나 외부 전문가 검토를 거치지 않았다. 컴퓨터 검증을 통과했다고 해도 검토자는 다음을 직접 확인해야 한다.
  - 최종 정리의 진술이 원래 문제와 정확히 같은가
  - 추가 공리, 미완성 증명(`sorry`), 검증을 우회하는 선언이 섞여 있지 않은가
  - 어떤 보조정리가 핵심이고 어디부터 읽어야 하는가

  이 분량을 사람이 처음부터 읽는 것은 불가능하다.
- **타겟 사용자**: AI로 형식 증명을 생성하는 수학 연구자와 연구실, 증명을 검토하는 학술지 심사자, Lean·Coq 등으로 소프트웨어·하드웨어를 형식 검증하는 기업 엔지니어
- **페르소나**: 대학 수학과의 박사후 연구원. AI 도구로 만든 수만 줄짜리 Lean 증명을 공동 연구자에게 넘기기 전에 "이 증명이 무엇을 가정하고 무엇을 증명했는지"를 한 페이지로 정리하느라 며칠을 쓴다.

## 3. 핵심 기능 및 차별점
| 기능 | 설명 | 기존 대안 대비 차별점 |
|---|---|---|
| 신뢰 기반 리포트 | 최종 정리가 의존하는 공리 목록, `sorry`, `axiom`, `unsafe`, `implemented_by` 같은 우회 선언을 전수 탐지 | Lean의 `#print axioms`는 정리 하나 단위라 프로젝트 전체 요약을 따로 만들어야 함 |
| 진술 대조 뷰 | 최종 정리의 형식 진술과 사람이 쓴 자연어 진술을 나란히 보여 주고, 정의를 펼쳐 차이를 표시 | "다른 것을 증명한" 오류를 잡는 데 초점 |
| 의존성 지도 | 보조정리 수천 개를 그래프로 압축하고, 많이 참조되는 핵심 보조정리를 순위로 표시 | 파일 트리가 아니라 논리 구조 기준으로 탐색 |
| 검토 분담 | 그래프를 독립 하위 트리로 나눠 검토자별 체크리스트로 배분 | 대형 협업 검토를 위한 작업 단위 제공 |
| 변경 추적 | AI가 증명을 다시 생성하면 바뀐 진술과 의존성만 diff로 표시 | 라인 diff가 아니라 정리 단위 diff |

## 4. 실행 계획 (MVP → 확장)
- **MVP 범위 (0~3개월)**: Lean 4 프로젝트(Lake)를 입력받아 공리·우회 선언 리포트, 의존성 그래프, 핵심 보조정리 순위를 HTML로 만드는 CLI와 GitHub Action. 만들지 않을 것: 증명 자동 생성, Lean 외 언어 지원, 자체 증명 검사기.
- **확장 1단계 (3~6개월)**: 자연어 진술 대조 뷰(LLM 보조), 검토 분담 체크리스트, 웹 대시보드
- **확장 2단계 (6~12개월)**: Coq·Isabelle 지원, 기업용 형식 검증 프로젝트(암호 라이브러리, 스마트 컨트랙트)용 감사 리포트 템플릿, 온프레미스 설치
- **기술 스택**: Lean 4 메타프로그래밍(환경 순회), Python/TypeScript 리포트 생성기, 그래프 시각화(Cytoscape.js), GitHub Actions

## 5. 수익 모델
- 오픈소스 CLI는 무료로 배포해 연구자 커뮤니티에 확산한다.
- 유료 대시보드(팀 검토 분담, 이력 관리)는 연구실·팀 단위 월 구독으로 판매한다. 가격은 1단계에서 인터뷰로 검증한다(가설).
- 기업 형식 검증 프로젝트에는 감사 리포트 작성 컨설팅을 건별 계약으로 제공한다.
- 첫 유료 고객 경로: 형식 검증을 납품 조건으로 쓰는 보안·블록체인 감사 기업

## 6. Go-To-Market
- 리만 가설 증명처럼 공개된 대형 Lean 저장소에 도구를 돌린 리포트를 공개해 인지도를 확보한다. 결과를 해석하는 글에는 "독립 검증 전"이라는 사실을 명확히 적는다.
- Lean Zulip, mathlib 기여자 커뮤니티, 형식 검증 학회 워크숍에서 도구를 시연한다.
- 첫 100명은 GitHub 스타와 Action 설치자에서 확보하고, 설치 저장소 운영자에게 유료 대시보드 베타를 제안한다.

## 9. 실현 가능성 점수: **4 / 5**
- **기술 난이도**: 중간. Lean 4 메타프로그래밍으로 환경을 순회하는 방법은 공개돼 있어 1~2인이 3개월 안에 MVP를 만들 수 있다.
- **초기 비용**: 낮음. 오픈소스 도구와 GitHub 인프라로 충분하다.
- **시장 진입**: 형식 검증 사용자층이 아직 작아 유료 전환을 검증해야 한다. 이 때문에 5점이 아니다.
- **수요 신호**: 2건(조선일보, 연합뉴스). 1740만 줄, 25만 쪽 설명, 독립 검증 미완료라는 사실이 검토 도구의 필요성을 보여 준다. YTN 항목은 2019년 해설 페이지라 근거로 세지 않았다.
