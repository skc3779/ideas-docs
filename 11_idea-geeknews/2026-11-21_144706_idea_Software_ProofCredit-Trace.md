# ProofCredit-Trace: Lean 증명·코드의 사람/AI 기여를 단계별로 기록하는 기여 증명 DevTools

## 1. 제안 범위 및 카테고리
- **영역**: 소프트웨어 (Software)
- **세부 카테고리**: DevTools / B2B SaaS
- **직전 실행과의 관계**: 신규

## 2. 해결 문제와 사용자 페르소나
- **문제 정의**: 한 수학자가 Lean으로 컴파일 가능한 리만 가설 해법을 발표하면서 마지막 단계에서는 Claude가 자신을 훨씬 앞질렀다고 밝혔다. 이후 AI의 성취가 인간의 주체성을 밀어낸다는 비판이 나왔다. 증명이나 코드가 기계 검증을 통과해도 어느 단계를 누가 했는지는 기록이 남지 않아, 저자 표기·심사·연구 윤리 판단에 쓸 근거가 없다.
- **타겟 사용자**: Lean/Coq로 형식 증명을 쓰는 연구자, AI 코딩 도구를 쓰는 연구소·기업 개발팀, 저널 편집자와 심사자
- **페르소나**: 대학 수학과 박사후연구원. Lean과 AI 어시스턴트로 보조정리를 채우고 있다. 논문을 제출할 때 "AI 사용 범위"를 적어야 하지만 수백 개 보조정리 중 어디에 AI 제안이 들어갔는지 기억에 의존해 적는다.

## 3. 핵심 기능 및 차별점
| 기능 | 설명 | 기존 대안 대비 차별점 |
|---|---|---|
| 제안 이벤트 로거 | VS Code의 Lean 확장과 AI 어시스턴트 사이에서 제안 → 수락/수정/거절 이벤트를 정리(lemma)·함수 단위로 기록 | Git blame은 커밋 작성자만 남기고, 사람이 고친 AI 제안과 AI가 쓴 원본을 구분하지 못함 |
| 기여 지도 | 증명 의존성 그래프 위에 사람/AI/혼합 기여를 색으로 표시 | 의존성 그래프와 기여 기록을 함께 보여 주는 도구가 드묾 (추정) |
| 기여 증명서 내보내기 | 논문 부록·PR 설명용 Markdown/PDF 리포트, 서명된 JSON 로그 | 자기 신고식 AI 사용 고지를 재현 가능한 로그로 대체 |
| 정책 템플릿 | 저널·기관별 AI 사용 고지 양식에 맞춘 자동 문구 | 고지 양식을 사람이 매번 직접 작성할 필요가 없음 |

## 4. 실행 계획 (MVP → 확장)
- **MVP 범위 (0~3개월)**: Lean 4 + VS Code 확장 1종, 로컬 SQLite 로그, Markdown 리포트. 만들지 않을 것: 자체 AI 모델, 클라우드 협업 기능, Coq/Isabelle 지원
- **확장 1단계 (3~6개월)**: 일반 코드 저장소용 Git 훅과 GitHub App, 팀 대시보드, 서명된 로그
- **확장 2단계 (6~12개월)**: 저널·학회 제출 시스템 연동, 기업 감사(AI 생성 코드 비율 보고)용 엔터프라이즈 플랜
- **기술 스택**: TypeScript(VS Code 확장), Lean 4 LSP, SQLite, Sigstore 계열 서명, Next.js 대시보드

## 5. 수익 모델
- 개인·학생은 무료. 팀 플랜은 사용자당 월 과금(가설: 월 10~20달러, 추정), 기업 감사 리포트는 연간 계약
- 첫 유료 고객 확보 경로: AI 생성 코드 비율을 내부 감사에 보고해야 하는 중견 소프트웨어 기업의 플랫폼 팀

## 9. 실현 가능성 점수: **4 / 5**
- **기술 난이도**: 중간. Lean LSP와 VS Code API만으로 이벤트 수집이 가능하며 새 모델이 필요 없다.
- **초기 비용**: 낮음. 1~2명이 3개월 안에 로컬 확장 MVP를 만들 수 있다.
- **시장 진입**: 형식 증명 사용자층은 좁아서, 일반 코드 감사 시장으로 넓혀야 유료 전환이 가능하다. 이 부분은 검증이 필요하다.
- **수요 신호**: 2건. AI가 Lean 증명에 결정적으로 기여했다는 발표와 인간 주체성 비판이 함께 나왔다. 다만 같은 사건을 다룬 기사들이다.
