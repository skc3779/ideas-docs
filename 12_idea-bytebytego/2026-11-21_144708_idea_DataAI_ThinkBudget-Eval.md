# ThinkBudget-Eval: 추론 예산별 정확도·비용 곡선과 데이터 신선도를 함께 검사하는 에이전트 평가 하네스

## 1. 제안 범위 및 카테고리
- **영역**: 데이터 및 인공지능 (Data & AI)
- **세부 카테고리**: MLOps / LLM App (에이전트 평가)
- **직전 실행과의 관계**: 신규

## 2. 해결 문제와 사용자 페르소나
- **문제 정의**: ByteByteGo가 "더 많이 생각하면 LLM이 오히려 멍청해질 수 있다"는 주제를 다뤘다. 추론 토큰을 늘리면 비용과 지연은 확실히 늘지만 정확도는 보장되지 않는다. 같은 주 「Evals for AI Engineers」에 실린 문구는 엔터프라이즈 에이전트 운영의 어려운 질문으로 에이전트가 어떤 데이터에 접근하는지, 데이터가 얼마나 최신이어야 하는지, 어떻게 범위를 지키게 할지를 꼽는다. 팀들은 모델의 추론 설정을 감으로 고르고, 근거 데이터의 신선도는 평가하지 않은 채 배포한다.
- **타겟 사용자**: 추론 모델을 운영에 쓰는 AI 엔지니어, LLM 비용을 관리하는 플랫폼 팀, 사내 지식 에이전트(RAG) 운영팀
- **페르소나**: B2B SaaS의 AI 엔지니어. 고객지원 에이전트에 추론 모델을 붙였는데 월 API 비용이 크게 늘었다. 추론 강도를 낮추면 품질이 얼마나 떨어지는지 데이터가 없어 결정을 미루고 있다. 고객 문의에 지난 분기 가격표로 답한 사고도 있었다.

## 3. 핵심 기능 및 차별점
| 기능 | 설명 | 기존 대안 대비 차별점 |
|---|---|---|
| 추론 예산 스윕 | 같은 평가셋을 추론 강도·최대 토큰별로 반복 실행해 정확도·비용·지연 곡선을 그림 | 일반 평가 도구는 모델 간 비교가 중심이고, 같은 모델의 추론 예산 최적화는 별도 작업 (추정) |
| 과잉 추론 탐지 | 예산을 늘렸을 때 정답이 오답으로 바뀌는 문항을 따로 모아 패턴 분석 | "더 생각하면 나빠지는" 사례를 회귀 테스트셋으로 자동 축적 |
| 데이터 신선도 테스트 | 에이전트 답변이 인용한 문서의 수정 시점과 유효기간을 검사하고, 오래된 근거 사용을 실패로 처리 | 정답 일치만 보는 평가에 시간 축을 더함 |
| 데이터 경계 검사 | 에이전트가 허용 범위 밖의 데이터 소스에 접근했는지 트레이스로 확인 | 평가와 접근 정책 점검을 한 파이프라인에서 실행 |
| CI 게이트 | PR마다 비용 대비 품질 기준을 통과해야 배포 | 프롬프트·모델 변경의 비용 영향을 배포 전에 확인 |

## 4. 실행 계획 (MVP → 확장)
- **MVP 범위 (0~3개월)**: Python CLI, 주요 LLM API 2~3종의 추론 설정 스윕, 곡선 리포트(HTML), 문서 메타데이터 기반 신선도 검사. 만들지 않을 것: 자체 모델 학습, 범용 프롬프트 관리 도구, 노코드 UI
- **확장 1단계 (3~6개월)**: GitHub Actions 연동, 과잉 추론 회귀셋 자동 관리, 팀 대시보드
- **확장 2단계 (6~12개월)**: 운영 트래픽 샘플 기반 지속 평가, 요청 유형별 추론 예산 자동 라우팅 추천
- **기술 스택**: Python, 오픈소스 평가 프레임워크(promptfoo·Inspect 계열) 플러그인 방식, OpenTelemetry GenAI 트레이스, DuckDB, Plotly

## 5. 수익 모델
- 오픈소스 CLI는 무료, 팀용 호스팅 대시보드와 CI 게이트는 월 구독(가설: 팀당 월 과금, 추정)
- 첫 유료 고객 확보 경로: LLM API 비용 절감 사례 리포트를 무료로 만들어 준 뒤 지속 평가 구독으로 전환

## 6. Go-To-Market
- "추론 예산을 절반으로 줄여도 정확도가 그대로인 경우" 같은 공개 벤치마크 글을 연재해 AI 엔지니어 커뮤니티에 배포
- 평가 프레임워크의 플러그인 마켓·GitHub에 배포하고, AI 엔지니어 밋업에서 비용 절감 데모 발표

## 9. 실현 가능성 점수: **4 / 5**
- **기술 난이도**: 낮음~중간. 기존 평가 프레임워크와 LLM API 설정만으로 구현할 수 있다.
- **초기 비용**: 낮음. 1~2명이 3개월 안에 CLI MVP를 낼 수 있다. 실험용 API 비용만 든다.
- **시장 진입**: 보통. 평가 도구 경쟁이 치열해서, 추론 예산 최적화라는 각도가 유료 전환으로 이어지는지 검증해야 한다.
- **수요 신호**: 2건. 과잉 추론 문제와 엔터프라이즈 에이전트의 데이터 접근·신선도 문제가 근거다. 다만 두 항목 모두 수집된 요약이 스폰서 문구 위주라 근거가 약하다.
